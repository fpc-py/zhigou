> 压测对象：本地全链路（BFF `10.206.185.162:3000` → 11 个 Java 微服务 + MySQL/Redis/RocketMQ 中间件）

## 1. 场景设计

黄金路径（登录 → 商品列表 → 商品详情 → 加购 → 下单 → 支付创建 → 我的订单 → 售后列表），读链路 80% / 写链路 20%：

| 接口 | 频率 | 说明 |
|---|---|---|
| POST /auth/login | setup 1 次 | 全局登录（redis 预置验证码），token 共享 |
| GET /product/page | 每次迭代 | 商品列表（size=20，最高频读接口） |
| GET /product/:id/detail | 每次迭代 | 商品详情（含 AI 摘要 RAG 调用） |
| GET /order/mine | 每次迭代 | 我的订单 |
| GET /aftersale/mine | 每次迭代 | 售后列表 |
| 加购→下单→支付创建 | 每 5 次迭代 | 写链路（20%） |

阶梯：100 → 500 → 1000 → 2000 VU（各 1 分钟 + 2000 持续 30s）
阈值：错误率 < 1%、P95 < 1.5s

## 3. 瓶颈分析（真实定位）

1. **product/page（最高频读接口）在 2000VU 下大面积失败**（33% 通过）：
   - 无缓存：每次请求实时查 MySQL（SPU+SKU 全量装配），连接池在高并发下耗尽排队
   - BFF 无响应缓冲/熔断，Node 单线程事件循环被阻塞（P95 10s 整体排队特征）
2. **BFF 层吞吐劣化**：峰值 RPS 176 远低于单层基线 718 —— Node 事件循环 + axios 连接复用不足（每次透传新建连接）
3. **product/detail 隐性拖慢**：BFF 日志显示 `ai-orchestrator RAG 失败: connect ETIMEDOUT 127.0.0.1:8000` —— 详情接口在 AI 摘要不可用时等待超时后降级，放大延迟（50VU 时已有 RAG 降级日志）
4. 写链路（加购/下单/支付）在混合压测中未成为主要失败点（幂等/事务保护生效）

## 4. 优化建议（P1，按收益排序）

| 优先级 | 优化项 | 预期收益 |
|---|---|---|
| P1 | product/page 加 Redis 缓存（热点 SPU 列表，TTL 60s + 失效通知） | 商品读接口 QPS 数倍提升，缓解 33% 失败 |
| P1 | BFF 全局 HTTP 连接复用（keep-alive agent + 连接池）+ 并发限制/熔断 | 缓解 Node 事件循环阻塞，RPS 回升至单层基线 |
| P1 | ai-orchestrator RAG 调用加快速失败（如 300ms 超时即降级，不回源等待） | 详情接口延迟显著下降 |
| P2 | product-service HikariCP 连接池调优（maximum-pool-size=20→50）+ Tomcat max-threads | 提升单服务并发上限 |
| P2 | 压测数据清理脚本（压测产生的脏订单/支付单清理） | 保障环境干净可复测 |

## 5. 复测计划

优化落地后重跑同阶梯（100→500→1000→2000），验收标准：
- 2000VU 错误率 < 1%
- P95 < 1.5s
- 峰值 RPS 环比提升
