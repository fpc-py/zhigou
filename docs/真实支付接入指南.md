# 智购 · 真实支付接入指南（沙箱 → 微信/支付宝）

> **本文档回答**：把当前沙箱支付（`SandboxChannel` + `POST /payment/sandbox/mock-pay`）替换为真实微信/支付宝支付，需要改哪些代码、按什么顺序落地、怎么验证。
> **读者**：payment-service / order-service / BFF / H5 开发者、发布负责人。
> **前置阅读**：`services/README.md`（服务表）、`docs/智购-企业级工程化技术方案.md`（一致性章节）、`services/payment-service/src/main/java/com/zhigou/payment/**`（现状代码）。

---

## 一、现状盘点（沙箱实现）

| 位置 | 现状 | 与真实的差距 |
|---|---|---|
| `channel/PaymentChannel.java` | 抽象接口 `createPayment(orderNo, amount)` + `verifyCallback(paymentNo, sign, body)` | 接口可复用，方法签名需要扩展（见 3.1） |
| `channel/SandboxChannel.java` | 返回假 URL；验签 `sha256(paymentNo + secret)` | 需替换为微信/支付宝渠道实现 |
| `controller/PaymentController.java` | `POST /payment/create`（userId/orderNo/amount，兼容 Number/String）；`POST /payment/sandbox/mock-pay` | create 保留；mock-pay 下线；新增真实回调入口 |
| `service/impl/PaymentServiceImpl.java` | create 幂等（同 orderNo 只建一单，paymentNo 唯一索引）；mockPay 验签 → `PENDING→SUCCESS` | 状态机保留；回调来源换成渠道异步通知 |
| `entity/Payment.java` | paymentNo/orderNo/userId/amount/status/channel/paidTime + `@Version` 乐观锁 + `@TableLogic` 逻辑删 | 可复用，建议加 `tradeNo`（渠道交易号）、`refundAmount` |
| `application.yml` | `payment.sandbox-secret: sandbox-secret-key` 写死 | 改为环境变量注入（见 5） |
| 订单联动 | `order-service POST /order/payCallback/{orderId}` 存在，但**由冒烟脚本手动触发** | 真实支付需由 payment-service 验签成功后自动调用 |
| 前端 H5 | `api/payment.ts`：createPayment + mockPay（sha256 沙箱验签）；checkout/orders/order-detail 三处直付 | 需改为「创建支付单 → 拉起收银台 → 轮询支付结果」 |

**当前支付成功链路（沙箱）**：
```
H5 submit/去支付
  → BFF /payment/create → payment-service create (PENDING)
  → H5 mockPay(sha256 验签) → payment-service PENDING→SUCCESS
  →（人为）order-service /order/payCallback/{orderId} → 订单 INIT→PAID
```
**真实支付目标链路**：
```
H5 提交订单
  → BFF /payment/create → payment-service create (PENDING) + 渠道下单（返回二维码/收银台参数）
  → 用户在微信/支付宝完成支付
  → 渠道异步回调 POST /payment/notify/{channel}
  → payment-service 验签 → PENDING→SUCCESS（幂等） → 通知 order-service → 订单 INIT→PAID
  → H5 轮询订单/支付状态，成功后跳转订单详情
```

## 三、后端接入实操（payment-service）

### 3.1 扩展渠道抽象（方法签名）

真实支付需要「渠道下单」返回**拉起支付所需的参数**（二维码链接 / 收银台参数），而不只是一个 URL 字符串。改造 `PaymentChannel`：

```java
public interface PaymentChannel {
    /** 渠道下单：返回拉起支付的参数（如 qrCode 链接 / 小程序参数 JSON） */
    ChannelPayResult createPayment(Payment payment, Map<String, String> extra);

    /** 渠道异步回调验签：返回支付成功与否；body 为回调原文 */
    boolean verifyCallback(String channel, String body, Map<String, String> headers);

    /** （可选）退款 */
    String refund(Payment payment, Long refundAmount);
}
```

`ChannelPayResult` 建议字段：`channelTradeNo`（渠道交易号）、`payParams`（JSON：qrCode/跳转参数）、`prepayId`、`expireAt`。

### 3.2 微信支付渠道（Native 扫码 / JSAPI）

**SDK 依赖**（`pom.xml` 新增）：

```xml
<dependency>
  <groupId>com.github.wechatpay-apiv3</groupId>
  <artifactId>wechatpay-java</artifactId>
  <version>0.2.14</version>
</dependency>
```

**实现骨架**（`channel/WechatPayChannel.java`）：

```java
@Component
public class WechatPayChannel implements PaymentChannel {

    // 密钥全部来自环境变量（见 3.5），禁止写死
    @Value("${payment.wechat.mch-id}")      private String mchId;
    @Value("${payment.wechat.app-id}")      private String appId;
    @Value("${payment.wechat.api-v3-key}")  private String apiV3Key;
    @Value("${payment.wechat.merchant-private-key}") private String merchantPrivateKey;
    @Value("${payment.wechat.notify-url}")  private String notifyUrl;

    @Override
    public ChannelPayResult createPayment(Payment payment, Map<String, String> extra) {
        // 1. 构造 Config（商户号 + 商户私钥 + APIv3 密钥 + 商户证书序列号）
        //    PrivateKey key = RsaUtil.loadPrivateKey(merchantPrivateKey);
        //    Config config = new RSAPublicKeyConfig.Builder()
        //        .merchantId(mchId).privateKey(key).merchantSerialNumber("...")
        //        .apiV3Key(apiV3Key).build();
        // 2. 调 Native 下单接口（二维码支付）：
        //    POST https://api.mch.weixin.qq.com/v3/pay/transactions/native
        //    body: { appid, mchid, description: "智购-订单" + payment.getOrderNo(),
        //            out_trade_no: payment.getPaymentNo(),   // 用 paymentNo 作为渠道单号
        //            amount: { total: payment.getAmount() },  // 单位：分
        //            notify_url: notifyUrl }
        // 3. 返回 code_url → ChannelPayResult.payParams = { qrCode: code_url }
        // 注意：body 里必须用 fastjson/Jackson 序列化，勿用 Hutool JSON（字段名会错）
        throw new UnsupportedOperationException("接入微信支付时实现，参考 https://pay.weixin.qq.com/docs/merchant/apis/native-payment/direct-js.html");
    }

    @Override
    public boolean verifyCallback(String channel, String body, Map<String, String> headers) {
        // 1. 取 headers：Wechatpay-Timestamp / Wechatpay-Nonce / Wechatpay-Signature / Wechatpay-Serial
        // 2. 用 APIv3 验签（SDK 提供 verifier），防伪造回调
        // 3. 解析 body：{ out_trade_no, transaction_id, trade_state: "SUCCESS", amount: { total } }
        // 4. 返回 trade_state == "SUCCESS"
        throw new UnsupportedOperationException("接入微信支付时实现");
    }
}
```

**要点**：
- `out_trade_no` 用业务 `paymentNo`（唯一索引已有），回调时凭它找到本地支付单。
- 回调验签是**安全底线**：不验签直接改状态 = 可被伪造回调刷单。
- `amount.total` 单位是**分**（与当前 `payAmount` 分单位一致，无需换算）。

### 3.3 支付宝渠道（当面付 / 电脑网站支付）

**SDK 依赖**：

```xml
<dependency>
  <groupId>com.alipay.sdk</groupId>
  <artifactId>alipay-sdk-java</artifactId>
  <version>4.39.74.ALL</version>
</dependency>
```

**实现骨架**（`channel/AlipayChannel.java`）：

```java
    @Value("${payment.alipay.private-key}") private String privateKey; // 应用私钥
    @Value("${payment.alipay.alipay-public-key}") private String alipayPublicKey;
    @Value("${payment.alipay.notify-url}") private String notifyUrl;

    @Override
    public ChannelPayResult createPayment(Payment payment, Map<String, String> extra) {
        // 1. AlipayClient client = new DefaultAlipayClient(
        //       "https://openapi.alipay.com/gateway.do", appId, privateKey,
        //       "json", "UTF-8", alipayPublicKey, "RSA2");
        // 2. 当面付 precreate：AlipayTradePrecreateRequest
        //    setNotifyUrl(notifyUrl); setBizContent({
        //      out_trade_no: payment.getPaymentNo(),
        //      total_amount: 金额(元，保留2位小数),   // 注意：支付宝金额单位是“元”
        //      subject: "智购-订单" + payment.getOrderNo()
        //    })
        // 3. 返回 qr_code → ChannelPayResult.payParams = { qrCode: qr_code }
        throw new UnsupportedOperationException("接入支付宝时实现，参考 https://open.alipay.com/api");
    }

    @Override
    public boolean verifyCallback(String channel, String body, Map<String, String> headers) {
        // 1. 用 alipayPublicKey + RSA2 验签（AlipaySignature.rsaCheckV1）
        // 2. 校验 app_id == 配置值；trade_status == "TRADE_SUCCESS"
        // 3. 校验 amount 与本地支付单一致（防止篡改）
        throw new UnsupportedOperationException("接入支付宝时实现");
    }
}
```

**要点**：
- 支付宝回调是 **POST form**（不是 JSON body），验签时要把所有参数（除 sign/sign_type）按 key 排序拼接。
- 金额单位：支付宝用**元**（`total_amount`），微信用**分**——两个渠道内部各自换算，`payment` 表统一存分。
- 支付宝验签**必须**校验 `app_id` 与回调 `seller_id`，否则跨账号伪造回调可成立。

### 3.4 回调入口 + 幂等 + 订单联动

**新增 Controller 路由**（真实回调与沙箱 mock-pay 并存一个版本，灰度期均可）：

```java
@PostMapping("/notify/{channel}")   // channel = wechat | alipay
public String notify(@PathVariable String channel,
                     @RequestBody(required = false) String body,
                     @RequestHeader Map<String, String> headers) {
    paymentService.handleNotify(channel, body, headers);
    // 微信要求返回 "SUCCESS"，支付宝要求返回 "success"（纯文本，非 Result JSON）
    return channel.equals("wechat") ? "SUCCESS" : "success";
}
```

**Service 核心逻辑**（`PaymentServiceImpl.handleNotify`）：

```java
@Transactional
public void handleNotify(String channel, String body, Map<String, String> headers) {
    PaymentChannel impl = channelFactory.get(channel);          // 按 channel 取实现
    if (!impl.verifyCallback(channel, body, headers)) {
        throw new BizException(403, "回调验签失败");
    }
    // 1. 解析出 tradeNo / paymentNo / tradeStatus
    // 2. 幂等：已 SUCCESS 直接返回（channel 幂等，重复回调不重复处理）
    // 3. 金额校验：回调金额 != 本地支付单金额 → 记审计日志并告警，抛异常
    // 4. status PENDING → SUCCESS；写 tradeNo；paidTime = now
    // 5. 支付成功后通知订单服务（见下）
}
```

**支付成功 → 订单联动**（二选一，建议先做 A，后做 B）：

- **方案 A（HTTP 同步，先落地）**：`RestTemplate/WebClient` 调 `order-service POST /order/payCallback/{orderId}`。注意：
  - 失败必须重试（重试 3 次 + 指数退避），最终不可达时进 outbox 兜底；
  - order 的 payCallback 已带状态机校验（INIT→PAID）与幂等（重复回调抛"不允许跃迁"——**建议给 order 侧加幂等**：PAID 时直接返回成功，见 3.6）。
- **方案 B（RocketMQ 事务消息，目标态）**：payment 写 outbox（topic `ORDER_PAID`）→ 投递任务发送 → order 消费改状态。与差距报告 P0「RocketMQ 事务消息」同一条线，一起做。

### 3.6 order-service 支付回调幂等（配套小改）

当前 `OrderServiceImpl.payCallback` 用状态机校验 `validateTransition(current, PAID)`——重复回调会抛 `ORDER_STATUS_ERROR`。真实支付回调可能重复，需要幂等：

```java
@Override @Transactional
public void payCallback(Long orderId) {
    OrderMain order = requireOrder(orderId);
    if (OrderState.PAID.equals(OrderState.from(order.getOrderStatus()))) {
        log.info("重复支付回调，幂等返回: orderId={}", orderId);   // 已支付，直接返回
        return;
    }
    OrderState.validateTransition(OrderState.from(order.getOrderStatus()), OrderState.PAID);
    order.setOrderStatus(OrderState.PAID.name());
    orderMapper.updateById(order);
    log.info("订单支付: orderId={}", orderId);
}
```

### 3.7 退款（售后资金流）

现有售后审批通过后**无退款资金流**（`aftersale approve` 只改状态）。真实支付下退款链路：

```
售后 approve → payment-service POST /payment/refund { paymentNo, refundAmount }
  → 渠道 refund（微信 refunds API / 支付宝 refund API，out_refund_no = 售后单号）
  → 回调验签 → payment.refundAmount += n；status 视全额/部分退款置 REFUNDED / SUCCESS
  → 通知 aftersale-service（HTTP 或 MQ）→ 售后单 → REFUNDED
```

`PaymentChannel.refund` 返回渠道退款单号；退款同样**幂等**（out_refund_no 唯一）。

## 四、前端接入实操（h5-shop + BFF）

### 4.1 流程切换（核心改动）

当前：`submit() → createPayment → mockPay → 跳订单详情`。
改为：

```
submit() → createOrder（不变）
  → createPayment（不变，BFF 透传）→ 返回 payParams
  → 拉起收银台：
       qrCode  → 弹二维码弹窗（扫码支付），同时开始轮询
       JSAPI/跳转参数 → router.push 收银台页 / window.location
  → 轮询支付结果（每 2s，最多 90s）：
       GET /payment/status/{paymentNo} 或 轮询订单详情 orderStatus == PAID
  → 成功后 showToast + 跳订单详情；超时提示"支付超时，可在订单页继续支付"
```

### 4.2 payment.ts 改造

```ts
/** 创建支付单：返回渠道拉起参数（真实接入后 qrUrl/payParams 由渠道提供） */
export async function createPayment(orderNo: string, amount: number): Promise<PaymentCreateResult> {
  const res = await http.post<{ code: number; data: PaymentCreateResult }>('/payment/create', { orderNo, amount });
  return res.data.data;
}

/** 真实支付：删除 mockPay 与 SANDBOX_SECRET（沙箱演示代码，上线前移除） */
// export async function mockPay(...) {...}   ← 删除

/** 支付状态轮询（需后端补 GET /payment/status/{paymentNo}） */
export async function getPaymentStatus(paymentNo: string): Promise<{ status: string }> {
  const res = await http.get<{ code: number; data: { status: string } }>(`/payment/status/${paymentNo}`);
  return res.data.data;
}
```

BFF 侧同步：`apps/bff-shop/src/payment/payment.service.ts` 透传 `/payment/status/:paymentNo`（如后端已提供），并**移除沙箱 mock-pay 透传**（或保留到灰度结束）。

### 4.3 轮询组件（checkout 页改造要点）

```ts
async function waitPay(paymentNo: string) {
  for (let i = 0; i < 45; i++) {          // 45 次 × 2s = 90s
    await sleep(2000);
    try {
      const st = await getPaymentStatus(paymentNo);
      if (st.status === 'SUCCESS') return true;
    } catch { /* 忽略单次网络错误，继续轮询 */ }
  }
  return false;
}
```

- 轮询**不阻塞**收银台（二维码弹窗内轮询，用户扫码后自动消失）。
- 页面卸载（`onUnmounted`）要清理定时器，防止路由切换后继续轮询。
- 支付宝/微信 JSAPI 场景前端只需要 `payParams` 调起 SDK，不需要自己轮询——**回调通知由后端驱动**，前端仅靠订单详情/列表刷新展示状态即可（订单页 load() 天然刷新）。

### 4.4 前端金额展示约束

- 结算页 `payAmount` 来自服务端聚合，前端只读展示；
- 支付弹窗金额**以订单详情/支付单返回为准**，前端不重新计算、不传自定义金额（`/payment/create` 的 amount 由 BFF 从订单取，前端透传订单 `payAmount` 即可）。

## 五、配置与安全清单

| 配置项 | 环境变量 | 必填 | 说明 |
|---|---|---|---|
| 沙箱密钥（灰度期保留） | `PAYMENT_SANDBOX_SECRET` | 否 | 接入真实渠道后置空并下线 mock-pay |
| 微信商户号 | `WXPAY_MCH_ID` | 微信接入时 | 商户平台获取 |
| 微信 AppID | `WXPAY_APP_ID` | 微信接入时 | 开放平台/公众平台 |
| 微信 APIv3 密钥 | `WXPAY_API_V3_KEY` | 微信接入时 | 商户平台「API 安全」设置 |
| 微信商户私钥 | `WXPAY_MERCHANT_PRIVATE_KEY` | 微信接入时 | PKCS#8，`-----BEGIN PRIVATE KEY-----` |
| 微信商户证书序列号 | `WXPAY_MERCHANT_CERT_SERIAL` | 微信接入时 | 商户证书序列号 |
| 微信回调地址 | `WXPAY_NOTIFY_URL` | 微信接入时 | **必须是公网 HTTPS** |
| 支付宝 AppID | `ALIPAY_APP_ID` | 支付宝接入时 | 开放平台应用 |
| 支付宝应用私钥 | `ALIPAY_PRIVATE_KEY` | 支付宝接入时 | RSA2，PKCS#8 |
| 支付宝公钥 | `ALIPAY_PUBLIC_KEY` | 支付宝接入时 | 应用公钥对应的支付宝公钥 |
| 支付宝回调地址 | `ALIPAY_NOTIFY_URL` | 支付宝接入时 | **必须是公网 HTTPS** |

安全红线：
1. 回调**必须验签**（微信 APIv3 验签 / 支付宝 RSA2 验签），不验签等于裸奔；
2. 回调金额与本地支付单金额**必须一致**，不一致 → 告警 + 拒绝入账；
3. 支付单/订单状态变更**必须幂等**（重复回调、重复通知都不重复处理）；
4. 私钥不进代码、不进 git、不进日志；回调 body 打日志前脱敏；
5. `payAmount` 以 order-service 存库为准，前端展示值不可信。

## 六、测试方案

| 用例 | 方法 | 通过标准 |
|---|---|---|
| 沙箱回归（灰度期） | 跑 `scripts/smoke/zhigou-e2e.ps1` | PASS 17/17（mock-pay 下线前保持） |
| 渠道下单 | 微信/支付宝**沙箱环境**下单 | 返回 qrCode/收银台参数，payment 落 PENDING |
| 回调验签 | 用渠道沙箱工具模拟回调（正确/错误签名各一次） | 正确签名→SUCCESS；错误签名→403 且状态不变 |
| 回调幂等 | 同一回调发两次 | 第二次直接返回，状态不重复流转 |
| 金额篡改 | 回调金额 +1 分 | 拒绝入账 + 审计日志 |
| 重复支付回调 → 订单幂等 | payment SUCCESS 后再回调一次 | order 仍 PAID，不抛状态机错 |
| 前端收银台+轮询 | 沙箱渠道下单 → 模拟支付 → 前端轮询 | 自动检测成功并跳转订单详情 |
| 退款链路 | 售后 approve → refund → 回调 | payment 记退款、aftersale → REFUNDED |
| 对账 | 跑 `PaymentServiceImpl.reconcile` | 无 PENDING 超 24h 异常单；或正确告警 |
